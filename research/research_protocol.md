# 多轮研究与推荐验收规范

状态：本轮 Agent 提案，待主对话确认；尚未执行工具调研。

## 分工与轮次
1. 需求轮：主对话明确场景、环境、预算、数据边界和验收样本。
2. 发现轮：研究 Agent 搜集官方能力说明及独立社区实例，形成候选和来源清单。
3. 反证轮：另一 Agent 独立查找失败、限制、付费与导出问题；先独立检索再读初评，减少互相附和。
4. 实测轮：按统一任务执行，保留输入、提示词、版本、原始输出、修改记录和计时；每个入围方案至少两次独立运行，记录波动。
5. 裁决轮：主对话逐项对照证据，分为推荐、条件推荐、待验证、淘汰。分歧不能靠多数投票抹去。
6. 演前复核：复查入口、价格、账号、教程步骤及现场网络；变化仅重测受影响环节。

初始预算建议两轮研究加一轮补缺；新一轮必须指出要解决的证据缺口。无新证据则停止，保留不确定结论，不无限循环。

## 来源与社区证据
每条记录：工具和版本、具体主张、原始 URL、发布时间、访问日期、任务条件、正反反馈、是否推广、支持/反驳什么、可信度与局限。
同源转载仅算一个来源；官方宣传不能证明真实用户满意度。每个入围项争取至少两条独立且有操作细节的社区实例，并主动查负面反馈；不足则明确降级，不虚构总体好评率。
社区口碑和本地实测分别记录；多个 Agent 重述同一网页不增加证据强度。

## 中国企业适配
逐项核实境内实际可访问性、账号注册、人民币支付及发票需求、中文效果、Office/WPS/飞书/钉钉兼容需求、编辑与导出、数据处理条款和公司许可。不要把国产品牌等同于符合公司要求。
先定义本公司硬条件，硬条件不满足则退出主推；其余维度按场景比较，不凭空打总分。

## 教程验收
用公开/脱敏材料，由未参与制作的人按步骤复现。记录账号与套餐、输入、提示词、操作、预期结果、人工核查、常见失败及替代路线。
耗时拆分为准备、生成、核查、修改和导出；质量采用预先定义的检查项，避免仅比生成速度。
未实际执行的步骤标为待实测，不写成可复现成功。

## 交付
每场景一张推荐卡、一份最小说明书、一个演示案例、一份证据清单。研究 Agent 只能维护认领范围；由主对话验收，不能自审为通过。
此规范是人工启动的多智能体执行方案，不是已部署的后台自主 Agent。
