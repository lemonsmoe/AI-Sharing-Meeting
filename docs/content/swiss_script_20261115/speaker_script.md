# 企业 AI 效率分享会｜照读稿

每页括号内是操作提示。页时见 [逐页分镜](outline.md)。

## 01｜AI 能交给我们什么

（停一拍，指向屏幕里的课件。）

大家下午好。今天这份 PPT，本身就是我想跟大家分享的第一个例子。我们准备它的时候，先有一份我写的大纲，然后把顺序理了一遍，拿几页试版式，最后再把内容一页页放进课件。如果会后有人想把其中一页拿去用，标题和表格可以在 PowerPoint 里接着改。

今天我主要讲三件事。第一，怎么把工作交代清楚，让 AI 给你一份可用的初稿。第二，怎么让它碰文件、做表格，怎么找一个现成的 Skill 来帮忙。第三，会议纪要、PPT、图和视频，现在分别能做到哪一步。大家可以边听边想一件自己刚做过的小事，等到最后看看有没有其中一步可以拿来试。

比如有人每周都要把同一组信息换个格式发出去，有人常常要回到会后记录里翻一个时间。先把这件小事记下来。等讲到你觉得用得上的地方，再记一句你会怎么给它下任务。

## 02｜这份 PPT 是怎么做出来的

（指旧样稿局部，再指新一轮三页缩略图。）

大家可以先看第一轮样稿。那一轮挑的是文字、关系图和表格，主要是看几种常见内容能不能排好。同一个版式放一句话可能挺好看，放上六行表格，行距、列宽、字号就都要重新考虑。关系图也一样，制作的人知道箭头往哪看，第一次看到的人可能会盯着两条交叉的线发愣。

我看完以后提了几个很实在的问题。用了太多种字号，主屏的字也偏多，有些解释完全可以放到讲稿里。左下角的页脚我也不想要。第二轮就换了三张来试，开场、讲提示词的一页，再加一张人物引语。这样能看出减字以后，开场能不能抓住注意力，教学页能不能看懂，引语页又能不能让观众停一下。

这几个环节里，AI 帮我处理结构和排版，哪些内容要讲、哪些案例能代表我们，还是我来定。后面到 PPT 那一段，我会把从大纲到成品的步骤再摊开一次。

## 03｜先从手头的一件小事开始

（依次指向三组输入和交付。）

如果你平时用不到代码，也能拿一件手边的小事试。手上有几份公开说明，可以把里面的同类信息放进一张对照表。收到一份很长的活动通知，可以先整理出时间、地点和要准备的东西。已经有一份提纲，可以先要三页汇报样稿，看看有没有说到点上。

有个办法可以判断第一件事选得合不合适。你拿到结果以后，知道应该打开哪份原文、看哪几个地方，就可以试。比如核对通知，比对三行日期和地址就行。第一次把任务缩到这个程度，几分钟内就能发现它有没有读懂，也容易知道下一句该怎么问。

我们平时把这些都叫 AI。可点开的软件、背后回答的模型、按钮能不能读文件，实际上是好几件事。下面拿一个大家熟悉的名字来拆开看。

## 04｜豆包和豆包模型有什么区别

（分别指 App 和型号，两边停顿。）

比如拿手机找豆包，我们点进去的是一个 App。发消息、上传图片、切换功能，这些都是产品给我们的使用入口。再看火山方舟，它列了一个具体型号，叫 Doubao Seed 二点一 Pro。这里说的模型，是其中负责处理输入并生成结果的一部分。

这和你在办公室看到一台打印机有点像。面板上你会选复印、扫描或者双面打印，里面也有负责各项功能的组件。AI 产品比这个例子灵活得多。同一个 App 可以在不同功能里用不同的模型或工具。同一款模型也可以从不同入口接入。我们看到一个型号出现在官方清单上，只能确认有这个型号，手机上每次提问实际用了哪一个，要看产品怎样提供信息。

如果同事说「我用豆包做的」，你可以多问一句，他用的是聊天、图片，还是别的功能。知道这一步，你回去才找得到相同入口。

模型名字记不住也没关系。记入口和当时给了什么材料，往往比单记一个品牌好用。尤其是要把做法教给旁边的人时，最好能从他打开 App 的第一步讲起。

## 05｜同一个问题，为什么有的 AI 能看文件

（指向两栏教学示意。）

假设桌面上有一份活动通知。你对一个聊天框说，「帮我看一下几点开始」，它收到的可能只有这句话。你把通知拖进去，它才有机会读到那份材料。换到一个能访问项目文件夹的应用，你也可以指给它看具体文件，前提是你已经给了相应权限。

搜索是另一个例子。一个应用能访问网页时，可以去找公开来源，另一个应用也许只能结合你贴进去的东西作答。再换一个工作场景，工具能生成文件，它就可能给你一份表格，只有文本输出时，你看到的可能是聊天里的表格预览。

所以下次问「为什么你做出来是文件，我这里就是一段字」，先看自己进了哪个功能，给了什么材料，界面有没有相应工具。能读、能写和能发出去，也可以是三种不同权限。我们后面讲办公 Agent，会用到这个区别。

## 06｜模型是怎么把句子写下去的

（先展示半句，等两秒，再出现两个候选。）

大家看屏幕上的半句话。「会议改到周……」后面填三还是五？只看这几个字，两种都说得通。如果上面还有一条通知，白纸黑字写了「改到周五」，你继续往下读，就容易选到五。

大语言模型生成文字，有个直觉跟这个相似。它把输入拆成一小段一小段的单位，根据看到的内容预测接下来可能出现什么，再接着生成。模型在训练中学过大量语言和信息之间的关系，所以可以延续一段话，也可以改写、归纳和回答问题。我们在聊天里提供的任务、附件和对话，又会给它当下可用的线索。实际产品还可以加搜索、文件和其他工具。

回到刚才那句话。如果旧通知写周三，新通知写周五，只把旧通知交给它，答案也许说得十分流畅，可你还是会去错时间。这个小例子也解释了为什么稍后我们要讲两件事，一是把当下的信息递给它，二是自己能找到原文核对。

## 07｜从看文字到看现场

（按顺序指文字、图像和机器人。）

文字只是其中一种信息。比如一张现场照片，你可以问 AI，「这张图里能直接看见哪几样东西？」再把相机挪个角度拍一张，它读到的内容又会变。也有模型可以处理音频或视频。能接收哪一种输入、能给哪一种输出，要看具体模型和产品。举个常见的情况，一个功能能读懂你传的照片，生成新照片可能要切到另一个入口。

再想象一下仓库里的搬运机器人。它得看到货架，避开挡路的箱子，然后真把东西搬过去。走一步，眼前的情况变了，就得再感知、再行动。这样跟环境打交道，是具身智能在讨论的问题。一个机器人完全可能同时用语言、图像和其他传感信息。多模态说的是它处理哪些信息，具身说的是它怎样在环境里行动。

今天我们会上手的，多数还是电脑和手机上的功能。开始前先练习一件最便宜的事，怎么把一句需求说清楚。

## 08｜一句「帮我改一下」少了什么

（先念左栏，再指向右栏三个条件。）

我把自己的 PPT 发给同事，跟他说，「帮我改一下。」他很有可能先反问我，「你是嫌写多了，还是嫌排乱了？」我在脑子里已经知道嫌哪里了，可这句话传过去只有五个字。给 AI 说也是一样。

拿这份分享举例，我可以这么交代。「明天下午给各部门同事和领导讲。先帮我改开场三页。保留已经选好的成果和事实，每页用一句标题带一个能看懂的例子，把细节写到讲者备注。」这几句话给了对象、范围和交付形式。拿到稿子，我可以直接数页数，也可以看主屏上一眼能不能找到这页要讲的事。

第一次写提示词，能把这三件事说出来就够用。对象是谁，你想拿到什么，拿到以后怎么检查。接下来再想，对方手里有没有做这件事所需的材料。

## 09｜把同事接手时会问的资料给齐

（停在两条不同日期的教学通知上。）

假设我们要发一条活动提醒。最初的通知说周三，之后补充通知改成周五。这是个教学例子。两份一起扔给 AI，只说「整理一下」，它可能照抄先读到的那个时间，或者把两个时间并排写出来。你可以在任务里补一句，「两份都看，安排冲突时以周二发的补充通知为准。找不到的地方写待确认。」

这里的上下文，就是它当下拿来完成任务的信息。比如哪份文件过时了，哪一列是含税价，哪段话是别人给的建议。这些在同一个部门里往往不用说，换个人接手，就至少要讲一次。

聊得很长时，我会在开始做下一步前，把当前决定重新写成一小段，注明最新版文件和还没解决的问题。比如「周五照常，地点以第二份通知为准，签到要求待确认」。这样你自己回头看也方便，模型处理这一轮时也有一份清楚的交接。

## 10｜给一个成品样子，比多写几个形容词有用

（指表头，停一下让大家看完示例行。）

刚才我们指定了用哪份通知。下一步，你还可以给它看一眼成品长什么样。比如我说，「把改动列成三列，调整事项、原安排、新安排。第一行我给个例子，活动时间，周三下午，周五下午。地点如果有调整，照这个样子另起一行。」一句「做得清楚一点」，每个人理解会不一样。一行例子给了它列名、粒度和填法。

工作里有现成格式时也一样。给一份可用的旧样式，让它参考标题层级或列名，明确告诉它新数据从哪里来。旧表里的行可以早已作废，把那些旧数值留给它当任务资料，反而会干扰。

有时做的东西根本没有模板。你可以先写一行自己肯定能验收的例子，让它按这一行继续填。连自己都定不下来的地方，请它列出需要你确认的两三项，先把范围划清。

## 11｜会提修改意见，才会把初稿变成成品

（手指跟着页面上的三个标注走。）

拿到初稿之后，我最常说的话可能是「太满了」。这对我自己是很明确的感受，对做稿的人却还要猜一次。是字号太小，还是三句并列的文字都在抢注意力？我后来会直接说到位置。比如「第二页右下角三行说明都放进备注，主屏只留一句结论。表格请保留原来的数字，我还要对着原件核。」第一次改的时候，可以只看一页，容易说清，也避免把已经对的地方一并改掉。

如果本来是做一份说明文，改法也差不多。「第一段要让同事知道今天要做什么，请把时间和动作提到开头；最后那段例行背景先留在原处。」对方做完，你就按这两句验收。

这就是为什么我稍后建议让 Agent 先做小样。它做的动作越多，你越需要在中间看一眼，确认它理解的交付，是你脑子里的那个东西。

## 12｜答案顺不顺，和答没答对是两回事

（指两条材料里的时间，再指错误摘录。）

再回到活动通知。上面写着周五，这一句总结却写了周三。语气很肯定，格式也很整齐，时间还是错了。这种把没有依据的内容说得像真的，是大家常讲的 AI 幻觉。有的错误是模型填了空，有的是读错、用了旧材料，或者把不同地方的信息混到了一起。

我通常这样查。先让它把关键结论后面标上材料名和位置，然后自己打开原文。看到有价格或合计，再用原数据算一下。搜索到了一篇很像的文章，也点开确认作者真正说了什么。可以请另一个 AI 专门帮忙挑错，但两个答案一致，仍然需要看原件。它们也可能恰好都读到同一份过时的资料。

这些动作能减少漏错。要对外发的时间、金额、承诺，还是由负责的人最后确认。接下来我们把刚才的提示和复核方法，放进一个真能处理文件的工作台。

## 13｜办公 Agent 可以接手哪些步骤

（指引言和人物署名。）

OpenClaw 的创始人 Peter Steinberger，在自己的博客里写过一句话。他说，他的下一个目标，是做出一个连他妈妈也会用的智能体。我喜欢这个说法。它把问题从「这个模型得多强」，改成了「普通人交代一句事，到底能不能拿回一个有用的结果」。这是他当时写下的愿望。

举个最简单的区别。你在聊天里说「把这三份说明的改动列出来」，它可以回你一段话。给一个有文件权限的办公 Agent 做，它可以打开你指定的文件，整理成表，再把表放回你给它的目录。中间它可能判断要先读哪一份，发现日期冲突也可以停下来请你确认。它能走几步，看它手里有哪些工具以及你开放了什么权限。

接下来几页，我们先看界面，再看怎么从一件小任务开始。你平时用的是 Codex 或者腾讯 WorkBuddy，都可以认一认这几样东西。

## 14｜工作台上先认三个地方

（指任务列表、目录、对话内的产出或文件链接。）

打开我平时用来做这份分享的 Codex 桌面界面，我先找三个地方。第一是任务列表。这里可以把大纲、讲稿、制作各放在自己的对话里。回到哪条对话，就接哪件事。第二是工作目录，我得知道它能在哪个文件夹里读写。第三是结果在哪里，Agent 说「我做完了」之后，要点开它给的文件实际看一遍。

两件事能并行的时候，开两个对话比较方便。拿这次分享来说，一边可以核对产品名称和来源，另一边拿已经确认的页题做排版样稿。等样稿出来，把锁定好的文字和照片交过去。让两个对话同时改一份课件，就容易出现一边更新了标题、另一边把旧标题写回来的情况。

界面随版本会变，左侧还是顶部不是重点。你只要能找到任务、目录和交付物，就能把第一件事安排下去。

如果你手头已有 Claude 账号，也可以看自己的版本有没有处理文件的工作功能。今天我们用 Codex 来认界面，下一页换 WorkBuddy，主要是让大家知道，换了产品以后还可以从哪几个地方找起。

## 15｜第一次只交一个小任务

（指向工作目录和新建任务入口，或展示静态操作示意。）

想用腾讯 WorkBuddy 试，可以从官网的新手指南下载并登录，然后新建任务。第一次我会选一个干净的文件夹，放两份自己可以分享的材料。比如两份公开的活动说明，在任务里说，「先找出时间、地点和参加方式的差异。给我一张表，每一行附来源。先告诉我会读哪两份文件，生成后放在这个目录里。」

如果它问你的授权，先看范围。读两个说明用不到整个文档盘。有格式要求，可以先让它回一行样例，确认列名和写法，再让它做完整表。等它说好了，打开文件查一行日期，看是否能按来源找到原件。要是有两处材料冲突，查看它有没有把冲突给你留下来。

到这里，你已经走完一轮了。从给材料、交代产出，到亲自验收。以后遇到同类工作，不必每次都从第一句重新教它。可以把固定步骤打包成一个 Skill。

## 16｜Skill 是能反复用的做事方法

（展示一个真实项目 Skill 的文件夹结构。）

大家可以把 Skill 想成一份放在工作台上的操作手册。最常见的形式是一个文件夹，里面有一份叫 SKILL.md 的说明，会写适合做什么、开始前要哪些材料、顺序怎么走。旁边可以放模板、参考样例，也可以附脚本。比如一个做 PPT 的 Skill，可能会写先列大纲，再选版式，最后按要求导出 PPTX。

如果我只是当天临时想看看一种设计，我在对话里写一句需求就够。遇到每次都要做的事，比如每回都按同样规范处理表格和讲者备注，就有理由把方法留下来。到了下一回，换的是内容，流程和检查动作还能沿用。

下一步大家最关心的通常是，现成的去哪里找，找到以后是不是直接装。我们就看这次做 PPT 用到的那个项目。

## 17｜去哪里找，怎样判断能不能用

（放大 PPT Master 仓库 README 中的样例、要求与导出信息。）

我的顺序是，先看产品有没有官方的 Skills 入口，也可以到 GitHub 看作者的原仓库。我会用任务描述去搜。比如我需要可编辑的 PowerPoint，就找「生成 PPTX、原生表格、模板」这些词。搜到 PPT Master，先翻它的 README，看有哪些实际样例、要装什么、最后出的是哪种文件，再打开样例判断合不合眼。

选之前再问三个很具体的问题。第一，它是否支持我手上的 Agent 或环境。第二，它带不带脚本，会访问什么。第三，我要的是打开能改的文字和表格，还是只需一份可看稿。这个问题会把很多看上去相似的工具分开。

第一次可以拿一份公开的大纲测试。先读安装说明，再按你所在产品的入口添加或启用。试三页，通过以后，再考虑用它处理合适的正式材料。直接动几十页，往往要到最后才发现导出的文件不合要求。

## 18｜Skill 找到了，怎么叫它做事

（点图上几个位置，最后回到本次任务。）

在 Codex 里，可以从 Skills 入口查看已启用的 Skill。具体叫法以界面所在版本为准。任务里明确点名以后，把材料和要求也写进去。比如「按 PPT Master 的流程做三页。读这份大纲，参考这份网格，先给封面、关系图、表格各一页，暂时停下来让我看。」跑完，打开文件点一下标题，表格也改一格，看它是不是真的能改。

我们把几个词顺便摆清楚。Prompt 是我刚说的这次任务。Skill 是可复用的步骤。MCP 是让 AI 应用连接外部工具和数据的一种协议，比如经授权读取某个会议服务里的记录。Harness 可以理解为外围的运行框架，管权限、工具调用、检查点以及中断后怎么接着干。Agent 结合任务和手里能用的东西往下走。

用的时候，记住眼下缺哪一部分就行。要获取纪要，先看能不能读到会议记录。要按规定格式整理，再找现成流程。下面我们就从一个会议开完之后的动作说起。

## 19｜开会前先找到纪要入口

（分别指腾讯会议和飞书的入口。用经核对的静态截图。）

先讲会议纪要。现成的会议软件一般离手边最近。比如电脑上开腾讯会议，会中可以找底部的「元宝笔记」，以前也叫「元宝纪要」。会后从「全部会议」进「历史会议」，打开那场会的详情。腾讯会议另有一个「AI 小助手」，可以用来提问。用飞书开会，可以查「智能纪要」。如果这场会录制后生成了妙记，也可以到飞书的会议历史或妙记主页里回看文字和录制。不同账号和组织配置，看到的按钮可能有差别。第一次用，提前开一场几分钟的小测试会，就知道自己的入口和权限。

真开会时先确认可以开启记录、谁可以看，尤其是有外部参会人的话。会议结束会拿到什么，要看刚才开了哪些功能。有的地方先拿到逐字稿，有的直接给摘要和待办。把它们留在会议工具里也好，交给获准的办公工具继续整理也好，接下来都会碰到同一个问题，一小时的话里面，到底有哪些事需要有人去做？

## 20｜从逐字稿到会后要做的事

（指屏幕上三列，停在「待确认」。用通用示意即可。）

开完会最怕一种纪要，看起来记录得很认真，大家读了，却不知道周一该干什么。可以让 AI 先按三类整理。已经定下来的事，哪些下次还得讨论，哪些是具体行动。行动再拆成事项、负责人和日期。原文找不到负责人或日期，就把空缺留下来，让人认领。

给到工具的指令可以很短。「请根据这份逐字稿和会后补充，生成一页纪要。决定、未决和待办分开。每条待办附上对应的原话位置。时间有冲突请列出来，已有明确更新的用最新确认。」如果平台能跳转到录音，也可以请它注明时间点。回头点到那一分钟，就能听到当时说的是什么。

大家会发现，这样要的是一份自己可以核的材料。就算有些地方没有定，空在那里也有价值，提醒主持人下一步要去找谁确认。

## 21｜发纪要前核这一遍

（沿着人名、日期、状态依次指一遍。）

拿到纪要，我会先看三类容易出错的信息。人名要看是不是行动负责人，有时候只是他说了这件事。日期要看有没有会后改过，有时候「下周前」还需要一个具体日期。状态要看是什么动作，有人确认「收到」，和这项工作已经交付，是两个阶段。金额、数量或者对外承诺，有的话也回原文查一遍。

查的时候，我会把逐字稿和纪要并排放在屏幕上，先挑那些出错会造成误解的行。比如让同事去错会议室、口头讨论被写成已批准。找不到来源，回到主持人那里核清，再改纪要。共享前别忘了看谁有权限，尤其是原始录音和逐字稿。

一个很简单的验收办法，是挑一项待办，让没听完整场会的同事读一下。如果他能说出接下来做什么、谁来做、什么时候交，这一行就能用了。剩下一项没分配，也应该让他一眼看出来。

这套做法可以用在手工纪要，也可以用在自动生成的纪要。下面的 PPT 流程也是同一回事，先想清楚最后要拿它做什么，再决定中途怎么用 AI。

## 22｜先选你需要哪一种 PPT

（左指浏览分享稿，右指可编辑文件。）

做 PPT 之前，我会先问自己一个问题。最后发出去，大家只要能看，还是过两天还要换部门名、改表格、接着用？如果只是发个链接让大家先看，可以试 Gamma 这类以网页呈现为入口的产品。官方也有导出 PowerPoint 的选项，导出后要按使用场景打开看一遍。如果公司统一用 PowerPoint，有现成模板，而且账号可以使用 Copilot，可以从带好标题和内容占位符的模板起步。

我们这次需要的是能继续编辑的 PPTX。打开它，应该点得到标题，表格能改一格，备注里能找得到对应讲稿。有人说「AI 做 PPT」，可能是模型先组织文案，生图工具生成素材，最后由工具把文字、图表、图片排进文件。哪部分需要接着改，要从一开始就告诉它。比如我可以接受照片本身是一张图，但表格和标题希望保留为可以选中的对象。

下面看我们在这份分享里怎么组合这些步骤。

## 23｜这套 PPT 的实际制作步骤

（按大纲、参考、三页样稿三个停顿展示。）

先说输入。我先写想讲的内容，列出必须有的主题和手边的例子。接下来把顺序拉成逐页分镜，确定每一页最重要的是哪句话、用什么图来说明、时间大概多少。有了这份分镜，做版式的人才知道哪页要放两列，哪页只要一张图。

然后把参考一起交给 Codex，指定用 PPT Master 这个开源 Skill 来做。比如我给一个参考网格，要求标题的左边对齐、不同页面的边距一致、表格离投影远一点也能看清。这些能直接检查，比一句「帮我做高级一点」容易落实。至于具体模型，第一次可以先用账号中稳定可用的一个，把材料、版式和要验收的项目说清楚。换模型时如果也换了模板和提示，很难判断差异从哪来。

这次先用第一轮的文字、关系图和表格检查内容怎么落版。后面换成开场、提示词和人物引语，再专门检查字有没有减下来，三种内容放在一起是不是还像同一份课件。这里有一步挺容易漏。给了参考图之后，要说清参考的是哪部分。比如用它的对齐和留白，文字仍然按这份新大纲来。改一轮后，把写清楚的要求带到剩下的页。整个流程里，顺序靠分镜先理清，版式靠样稿先试过，最后拿到文件还要打开检查。现在看成品里有哪些地方可以直接改。

## 24｜打开 PowerPoint 看能不能改

（用当前交付版做演示。若现场设备不便打开编辑视图，展示已核过的对应截图。）

大家看这张表。打开 PowerPoint，可以单独选中标题，再选中表里的一个单元格，点进去改这一处。这个动作能把「看着像一张表」和「会后能继续用这张表」分出来。下一次要换一行资料，自己改完就可以拿去用。我还会打开讲者备注，看这一页的备注是不是跟当前标题和内容对得上。

接下来切到放映视图。电脑上看起来还行的小字，放到会议室墙上可能就读不清。所以互相独立地看两件事。编辑时看对象能不能选、源数据能不能维护，放映时看字号、行距、有没有被遮住。以公司模板为底做的，可以顺便看看页脚和字体有没有走样。

如果你明天只想试一次，拿旧的三页公开材料做个副本，把新标题和一张表放进去，照刚才三个动作检查一遍就行。后面的图和视频，虽然用的模型变了，先定成品再试一个小样的做法还能沿用。

## 25｜即梦、小云雀，分别打开什么

（指产品入口与模型名。停在视频示例缩图，不现场播放未经确认的素材。）

大家在红果短剧上能看到一个「AI 剧」分类。那是作品的观看入口。如果想自己做图或试一段镜头，可以去看即梦和小云雀这类创作工具。以模型的名字举例，字节 Seed 团队发布了生图的 Seedream 五点五，也发布了生视频的 Seedance 二点五。即梦是可以体验它们的产品之一，小云雀的官方手册也列了 Seedance 二点五的视频功能。实际打开时模型的可用情况可能随账号和上线进度变化。

第一次试，可以按手上的素材选入口。只有一句描述，就从文生图起步。有一张可以使用的参考图，可以看看能不能让工具保持主体、换个角度或改背景。想试视频，先做一个短镜头。用一张认可的图当参考，先把最关键的动作跑通。剪成完整片子还要管镜头对接、字幕、声音和人物在每段里是否一致。今天我们先看看怎样把一个画面交代清楚。

## 26｜生图写清画面，生视频再交代动作

（先指左侧构图，再按顺序指右侧三个镜头格。）

比如我想要一张放在部门分享里的配图。可以这么写。「生成一张横版十六比九的插图。午后的会议桌旁有一台打开的笔记本电脑和一本便签本。画面主要物体放右半边，左侧留白给标题。用靠窗的自然光，蓝灰色调，画面里没有可见文字。」这样我可以按几件事来挑，桌上的东西是不是我想要的，左边能不能真的放下标题，光是不是太抢眼。

做成视频时再加动作。「大约五秒，从便签本慢慢移到打开的电脑。镜头平缓，人和物体位置保持一致。」如果一个镜头里连物体都变形，就先改这个镜头。做广告样图一类东西，还要照着真实产品图确认外观，尤其是尺寸比例、接口位置和商标。需要准确出现的品牌文字，可以在后期自己加，再按正常的发布要求核对。

这是一段拿来试构图和动作的教学提示。下面我们回到一个更小的尺寸，群里发出去的表情包。

## 27｜一组公司群表情包能怎么做

（有用户提供且获准展示的原件时，先给观众几秒看图。素材缺席时展示方法文字，直接朗读正文。）

我自己也用 AI 做过公司的表情包。表情包和 PPT 配图有一个很明显的区别。有人在群里扫一眼，大概一秒就要明白它的意思。图很精致、缩小后看不清，还是不好用。

如果要做一套，我会从使用场景开始。先想清楚大家是在确认收到、打个招呼，还是想表达「我这就来」。这里只举消息场景。再选一张有表情、有动作，而且缩小也识别得出来的图。字可以后配，先发到自己的测试窗口，看看手机上认不认得出。如果要做几张同系列的，定住角色、线条和用色，只改动作。这样大家一看就知道是同一套。

这个尝试比较容易起步，因为拿到一张图就可以自己判断用途。等到要持续做图、给同事开账号，或者想让工具一次处理更多材料时，就需要算清楚用的是哪一类服务。

## 28｜订阅、API、本地部署怎么算

（指三个成本栏；报价入口留在资料中。）

先说大家最常接触到的，账号订阅。交月费或使用免费档的时候，要看你真正想用的文件功能、模型和用量能不能覆盖。比如你只想试几次短文改写，先用现有额度就够。要经常处理长文档，得看看上传、调用次数或者共享方面的限制。在工具里点了某个高级功能，和买到了多少 API 用量，是两套账。

API 更像让程序调用服务。以 DeepSeek 的公开价目表为例，输入和输出各自计价，命中缓存和时段也可能影响单价。要比费用，用同一类任务估计一个月大概多少输入、多少输出，以及是否还要加搜索或文件工具。今天把实时价格入口放在资料里。

本地部署则是把可以部署的模型放在自己的设备或服务器上跑。要考虑模型权重和许可、内存或显存、响应速度，还要有人负责运维。如果本地工具同时会去云端搜索、调用接口或同步文件，也要看数据实际流向哪里。选哪一种，先算你的用量和已有设备，再看材料适合放到哪里。

## 29｜交给 AI 之前，先决定哪些能给

（指输入侧和发布侧两个停点。）

刚才说部署，最后是回到日常那句「这份东西能不能给它？」我会在两个地方停一下。第一次是发材料之前，先看资料是否可以给当前工具处理。公开材料容易练手，内部文档就看现行公司规则和授权。能只给两份文件，就选两份。要用场景练习，可以先用虚构名字和数据把流程走通。

第二次是拿到结果以后。改日期、给客户发话、确认金额，至少要有人看。比如 AI 写了一份邮件，外面看见的是发件人和公司。需要确认的承诺、附件和收件人，发之前都由经手人核一下。工具如果具备直接发出去的权限，先让它给你看草稿和对象，确认后再决定。

到了这里，大家也能看到一天里的分工。整理材料、先给个样子，工具能帮着做。选哪个方向、认哪份证据、最后交给谁，仍然需要熟悉事情的人。

## 30｜做 PPT 是手段，把事情讲明白才是目的

（指引文，读完停一拍。进入问答前让观众记下一个任务。）

黄仁勋在英伟达一份年度可持续发展报告的寄语里说，写代码是一项任务，创新才是目的。我借这句话说说今天这份分享。做 PPT 是手段，把事情讲明白才是目的。有了初稿以后，更重要的时间可能会花在想听众需要什么，哪张图能让他看懂，哪句话给了他一个可以带回去的动作。

也不用猜自己的工作以后到底会变哪样。找你下周本来就要做的一件事，比如整理一条通知，或者把已有提纲改成三页。拿允许使用的材料，写清交付，然后自己按原件核一遍。对提示词有兴趣，可以看 OpenAI 的入门短文，也有吴恩达和 Isa Fulford 面向开发者的短课。想开始用工作台，WorkBuddy 的首个任务指南和 Codex 快速入门都放在资料里。

如果今天要带走一句实际能用的话，可以先写到备忘录里。「帮我用这两份材料做一页，告诉我每条信息从哪里来，有冲突的先留给我确认。」下次把文件和交付形式换成你的，就可以试一遍。

今天就讲到这里。大家如果手上有一件事，想知道哪一步能交给 AI，可以现在提出来，我们一起把第一条任务说明写清楚。谢谢大家。
