## 讲稿需要明确或补完的内容

1. **P27、P28 还不是完整照读稿。** P27 的“可以告诉大家、找几条视频、链接可以放在 PPT 上”仍是写作安排；P28 在问会员、费用、部署条件，却没有作答。PPT 内的备注也包含这些问题，不能只修 Markdown 后忘了同步。建议 P27 改成已经选好入口后的现场话术；P28 补一段约一分钟的完整解释：订阅买产品功能与额度，API 按调用用量付费，本地部署承担设备、模型许可和维护成本。不写无比较口径的“DeepSeek 比较便宜”。

2. **P15 与 P22 对“许愿机”的说法冲突。** 前面提醒 AI 不是完美许愿机，后面却说“许愿许得够精确，它就能把任务干出来”。保留用户喜欢的老板/员工比喻，建议改成：“你负责目标、资料和验收；它在已有工具和权限范围内做执行。”

3. **P18、P19 的保证性用语收紧。** MCP 的“接上就能用”改为“按共同标准连接，仍要看支持情况、配置和授权”；Harness 的“保证 Agent 不会乱来”改为“约束权限和执行过程，重要节点仍要检查”；Agent 不等于保证每个任务从头到尾成功。P19 的 Prompt → Skill → MCP → Harness → Agent 不宜画成必经链条。可用同一任务说明各自职责，同时讲明不是每个任务都用到全部组件。

4. **P08、P09、P13、P16 避免过度简化。** 没给活动通知，是“缺少判断开始时间的材料”，不是“不理解需求”；生成过程可说“根据上下文估计后续内容的概率并生成”，不必暗示总选唯一最高概率；长对话不等于所有产品都会反复压缩；训练时“没法区分真伪”太绝对。幻觉的形成也涉及训练、评估和不确定性处理，列两个例子时不当完整归因。多个 Agent 一致仍不替代回原文核对。

5. **P04、P29 的事实与个人观察分开。** 有视频生成能力，不能推出红果/抖音上的“很多作品就是小云雀生成的”。建议改为“这类作品可以用小云雀等工具制作”。“绘画 → IT → 数学”的行业受影响先后不能由几个发布节点证明；可说“绘画、编程、数学等领域都出现了明显进展”，或明确这是讲者个人接触的顺序。现有 factcheck 文件的“错误 0 处”不应继续当总审结论。

6. **P23 的表格验收缺演示对象。** 当前 29 页 PPTX 没有原生表格；口头却让人“改一格表格”。可以在 P22 做一张原生结果表，再供 P23 指向；或把这段改为本稿确实具备的标题/段落编辑验证。不要把多个文字框画出的表格叫可编辑的原生单元格。

7. **P26 的通用提示词与公司表情包没有生成来源关系。** 现有原件可以展示，但当前“卡通形象、摊手、三种颜色”的教学提示并非已核实的原始提示，且没有描述红色标识角色、服装等。建议标“演示改写”，强调先提供角色参考；若讲原始制作过程，再用用户的真实原提示与参考图。

8. **减少同一个流程的反复讲述。** 保持页序也可解决：P12 只讲第一条任务怎么写；P14 讲参考具体参考什么；P15 展示一条反馈造成的版面变化；P23 展示怎样调用 Skill；P25 回顾真实制作产物。P02 用大图给成果，少重复 P25 的流程。
