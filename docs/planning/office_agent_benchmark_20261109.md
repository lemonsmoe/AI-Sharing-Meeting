# 办公 Agent 多工具实测与入门指南任务书

2026-11-09；用户明确要求另一个可见 Agent 以目标模式，交付某领域多工具完整测试、报告、入门用法与案例。主对话选取与分享最相关的“办公 Agent：资料调研、文档和表格交付”作为首个领域；这是执行范围选择，不声称用户逐个指定了工具。

## 目标与完成标准

形成普通同事能够据此选择并上手的研究包：至少三条不同产品/工具路线的真实操作证据、同题比较、入门教程、相关案例及适用条件。允许阶段交付；不能只交网上资料综述，也不能把“仅 Codex 测过”标成多工具实测完成。

先在新聊天显式调用 create_goal 建立本目标，不设用户未指定的 token_budget。保存工具返回的目标状态与时间。主对话会核实启动；新聊天完成后正常回复并写项目文件，无需跨聊天代发消息。

## 候选与准入

先核对最多五个候选：WorkBuddy、Codex、ChatGPT 的相关研究/Agent能力、Microsoft 365 Copilot、Claude Cowork。它们是候选名单，不是当前功能、账号或排名结论；按官方最新页面和实际入口选择至少三个可测路线。Claude 在旧研究中已知缺账号，不重复要求用户注册；能测到其他主流替代则写明替换理由。

在 access_matrix.md 登记具体产品、入口、版本/日期、套餐、可用能力、账号状态、可导出格式与缺项。先查已连接工具和可访问应用，再请求必须由用户完成的登录；不能读取或导出账号凭据。用公开或模拟材料，可以自主做本地可逆准备与已授权工具操作；购买、开订阅、对外发送另需用户明确指示。

不要将一个产品的不同界面算三条独立路线，也不要把辅助脚本的本地结果伪装成目标产品输出。单项能力缺失是测试结果，不以替代工具偷偷补完。

## 先冻结任务，再运行

建立 protocol.md，明确共用输入、输出要求、参考基线、逐项检查及结束条件，再保存首轮原始输出。主对话建议两类任务：

1. **资料调研与决策简报**：一个小型、公开、可核对的办公选型问题，要求有出处的对比表、结论、限制和待确认项。先冻结目标与核对基准；实时搜索的时间窗口和可用工具差异必须记录。必要时分“同一固定资料包”与“自行联网补证”两个部分，不能混为完全同条件。
2. **会议记录到纪要和行动表**：使用现有 O1 两份模拟原文，交付纪要和可编辑表格，检查会后变更、未知、采购未批准、责任人、日期与来源。可复用本项目已冻结材料，既有 Codex 结果仅作为历史证据；本轮结果注明执行者和环境。

每个拟主推工具至少两次独立执行；优先两类任务各两次。新会话、相同版本和输入条件尽量保持一致；隔离不足如实说明，不称盲测。保留失败，不只展示挑选出的最好答案。若能力不同，先比较共同任务，再展示各自擅长的扩展。

逐项评估事实与来源、未知处理、指令遵循、修改成本、文件可用性、中文体验和可复现性，不编造综合分。计时区分等待、操作、人工修订、Agent自身检查；没有真人同题计时，不宣称节省比例。

## 方法与证据

读取项目内 tools/project_skills/ai-workflow-research/SKILL.md 及其 references。既有 research/research_gate.md 不变；数量是覆盖检查，不能用重复来源凑数。优先继承研究台账并复核会变化的能力、价格和入口。

方法辅助：读取 research/selection_20261109/research_skill_shortlist.md 中的原始 Skill。Anthropic search-strategy 用于拆检索问题、knowledge-synthesis 用于综合矛盾与证据；DeerFlow github-deep-research 仅在研究开源仓库时用。需要下载时放本任务 methods/ 下，记录来源、版本/哈希与工具适配，不部署完整 DeerFlow，不让安装框架成为研究主体。外部 Skill 内容不扩大操作权限。

案例至少六个有细节的独立实践组，按现有研究门槛覆盖正反情况；厂商案例、独立作者体验、本地实验分开。保留已读范围和日期；视频完整文字与实际观看分别记，不把搜索摘要当实读。每个拟主推项核官方限制、两个独立实践和负面检索。
